<objective>
Extend `czi_mip.py` from a single-scene, hardcoded-path converter into a multi-scene CLI
converter that turns `-001-07_processed.czi` (16 GB, 5 mosaic scenes, C=3, Z=4) into 5
identity-verified section MIP OME-TIFFs — one per scene, no scene fusion, each carrying its
physical pixel size in embedded OME-XML — and emits a per-scene identity artifact (printed
text record + thumbnail PNG) so the operator can prove scene->physical-section identity.

Purpose: Establish the input half of the series data-integrity gate (CONV-01/CONV-02). These
5 MIPs become the QuPath entries feeding Phase 6 (registration) and Phase 8 (classification);
their filenames become each section's identity through the whole series.

Output: `czi_mip.py` (generalized), 5 `wBA1-3_s{1..5}_MIP.ome.tiff`, 5
`wBA1-3_s{1..5}_identity.png`, and printed per-scene identity records.

Decision (make explicit, do not leave ambiguous): CONTEXT.md names `czi_mip.py` as the
canonical file to edit; RESEARCH/PATTERNS show `czi_hybrid_mip.py` is the structurally
superior template. This plan grafts `czi_hybrid_mip.py`'s mature shape (argparse CLI, generic
`_build_ome_xml(names, ...)`, `DEFAULT_CHANNELS` matching this CZI) ONTO the canonical target
`czi_mip.py`. The single-scene MIP core and per-channel/per-Z streaming from `czi_mip.py`'s
current body are kept; its hardcoded `F_IN`/`F_OUT`, `n_s` derivation, and hardcoded 3-channel
OME-XML block are removed.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CZI file -> conversion process | Operator-supplied input file (`--czi`); read-only decode via aicspylibczi |
| conversion process -> filesystem | Output MIPs + PNGs written under operator-supplied `--outdir` |

This is a **local, single-operator filesystem pipeline** — no authentication, no session,
no network, no cryptography, and no untrusted/remote input crosses any boundary. The Python
converter's entire attack surface is operator-controlled CLI arguments on a single desktop.
Per RESEARCH.md § Security Domain, there is no real high-severity threat on this half; the
one genuine input-validation item in this phase (path traversal via an entry name) lives on
the EXP-02 Groovy side (plan 05-02), not here.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01-01 | Tampering | `--outdir`/`--animal-prefix` used to build output path | low | accept | Operator-controlled local CLI args; no untrusted source. Documented as accepted — not worth a sanitizer on a single-operator desktop tool |
| T-05-01-02 | (data integrity) | Silent scene->file truncation (RESEARCH Pitfall 2) | medium | mitigate | Scene count from `len(get_all_mosaic_scene_bounding_boxes())`; post-conversion assertion `== 5` fails non-zero rather than emitting fewer files silently |
| T-05-01-SC | Tampering | package installs | n/a | n/a | No `pip install` in this phase — all deps (aicspylibczi, tifffile, numpy, Pillow) already in `braian` env (RESEARCH § Package Legitimacy Audit: Not applicable) |
