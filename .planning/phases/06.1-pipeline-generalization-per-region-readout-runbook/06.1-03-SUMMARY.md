# Phase 06.1 Plan 03: Consolidated Config-Driven Per-Region Export Summary

**Fused `export_region_dapi_reference.groovy` and `03_export_val01_metrics.groovy` into one config-driven `03_export_region_table.groovy` that emits a per-cell TSV, a per-slice region count+density table, and a growing long/tidy combined CSV, with parent rows computed by a leaf-anchored ancestor walk (never independent parent-ROI counting) and a fail-loud zero-leak assertion.**

## Performance

- **Duration:** ~12 min
- **Completed:** 2026-07-23
- **Tasks:** 3/3
- **Files modified:** 3 (1 canonical + 2 byte-identical deploy copies)

## Accomplishments

- Authored `scripts/03_export_region_table.groovy` (507 lines): the same `pipeline.yml` line-block reader and three D-15 fail-loud asserts as `02_detect_classify.groovy` (ABBA ROIs present via `getAvailableAtlasRegistration`, detections present, config-declared channels match the image), followed by the CR-01 geometric region resolution (`regionOf` smallest-area-containing, `isLeafOf`, `regionLabel`) reused verbatim from `03_export_val01_metrics.groovy`
- Per-cell TSV (`results/<stem>__percell_export.tsv`) generalized to iterate `pipeline.yml`'s declared markers: one `<marker>_bgsub` column per declared non-anchor marker (no fixed Fos/TdT pair), nucleus area computed from ROI geometry (never a stored shape measurement), per-entry non-clobbering stem (`safeName__id<entryId>`) reused verbatim from the EXP-02 fix
- Leaf-anchored tally: each classified, non-excluded cell increments an "own-bucket" counter map keyed by its CR-01-resolved region annotation — anchor total (every non-excluded nucleus), per-marker positive count (including Double+), and Double+ itself when `emitDouble`
- **NEW** ancestor-walk parent rollup: walks each contributing annotation's `ann.getParent()` chain (already resolved by `01_load_abba_rois.groovy`'s `resolveHierarchy()`) and adds its own-bucket counts into every ancestor still in the candidate region set — no independent centroid-in-parent-ROI containment pass, satisfying D-10's zero-leak guarantee
- Fail-loud zero-leak assertion: sums all own-bucket anchor-category counts and aborts with `RuntimeException` (printing both numbers) if the sum does not equal the total non-excluded classified detection count; unresolved cells (no containing region) are counted and reported separately for diagnosability
- `results/<stem>__region_table.tsv`: one row per region annotation (leaves AND parent rollups) with `region_label, hemisphere, acronym, is_leaf, area_mm2` plus per-declared-category count/density columns (`density = count / area_mm2`, D-11); columns adapt to the declared marker set (D-04)
- `reference/region_marker_combined.csv`: header-guarded idempotent append (`slice,config_tag,region,hemisphere,is_leaf,marker,class,count,density`, D-13), `config_tag` regex-grabbed from `BraiAn.yml`'s detection params (verbatim idiom, keeps D-14's `pipeline.yml`/`BraiAn.yml` separation) — one row per region x declared-category, leaves and parent rollups both
- Deployed byte-identical copies to both QuPath project `scripts/` dirs (`M3 Hippocampus 20x 062926 3 plane/`, `wBA 1-3 2-1 072026/wBA_1-3_2-1_072026/`)

## Decisions Made

- The export reads the class vocabulary already written by `02_detect_classify.groovy` (`getPathClass()`) rather than re-deriving thresholds from the classifier JSONs — this script is a pure readout of an already-classified entry, matching the contract stated in the plan ("Contract consumed from 06.1-01: bg-sub key ...; class vocabulary")
- Two distinct naming closures are kept deliberately separate: `columnPrefixFor` (wide-table column prefix — anchor gets NO `+`, matching `validate_pipeline_config.py`'s `derive_contract()` columns) vs `classFor` (combined-CSV class label — anchor DOES get a `+`, per D-13's literal wording "class = `<anchor.name>+`"). Collapsing these into one function would silently break one of the two established contracts.
- The zero-leak assertion is scoped to the anchor category's own-bucket sum vs. total classified — this is stricter and more diagnosable than asserting on a rolled-up parent total, since any cell resolving to no region at all (`regionOf` returns null) is caught and reported by count rather than silently dropped
