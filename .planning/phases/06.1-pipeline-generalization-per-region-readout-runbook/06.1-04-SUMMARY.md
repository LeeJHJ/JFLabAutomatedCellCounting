## Accomplishments

- `build_dapi_reference.py`'s `load`/`aggregate` now key on the D-13 long/tidy schema (`config_tag, marker, class, hemisphere, region`) instead of a DAPI-only per-region shape; default input is `reference/region_marker_combined.csv`
- New `--check-zero-leak` mode: for each `(slice, config_tag, marker, class)` group, asserts `sum(count where is_leaf) == max(count where NOT is_leaf)` (the atlas root, as ancestor of every leaf, holds the largest cumulative count) — a second, independent witness of the D-10 invariant that `03_export_region_table.groovy` already asserts in-script
- New `--self-test`: builds a synthetic 2-leaf/1-root TdT-only combined CSV via `tempfile`, proving the aggregate groups by marker/class with zero fabricated Fos rows, and that `--check-zero-leak` passes on a consistent tree and fails when a leaf count is corrupted — runnable today, with no live QuPath export required
- `verify_export_integrity.py`'s `PERCELL_SUFFIX`/`REGION_SUFFIX` repointed to `__percell_export.tsv`/`__region_table.tsv`; pairing/non-clobbering assertions untouched (they key purely off the suffixes)
- `val01_metrics.py` generalized: `detect_marker_bgsub_columns()` scans the per-cell TSV for whichever `<marker>_bgsub` columns are actually present, replacing the hardcoded `fos_bgsub`/`tdt_bgsub` pair; the Double+/TdT+ ratio metric skips (printing a note) when `TdT` is absent or fewer than 2 markers are declared (Double+ can never exist per D-03), and the Fos+ control-rate metric skips when `Fos` is absent — while DAPI density-per-region and nucleus-area-peak (both marker-agnostic) always compute
- Manually smoke-tested `val01_metrics.py` end-to-end against a synthetic TdT-only per-cell/region TSV pair (beyond the plan's `ast.parse`-only automated check): both marker-dependent metrics printed `SKIPPED` cleanly, DAPI density and nucleus-area-peak computed correct values, no crash

## Decisions Made

- `load()`'s dedup now keeps file order (`keep='last'`) rather than sorting by a `timestamp` column, since the D-13 long/tidy schema has no timestamp column — the header-guarded idempotent append already makes file order equal recency.
- `--check-zero-leak` is a standalone mode: it prints PASS/FAIL and exits without also running the aggregate/stats-file write, keeping it narrow enough for scripted/CI-style invocation.
- The Double+/TdT+ ratio and Fos+ control-rate metrics are *skipped* (return `None`, printed note), not reported as `0`/`NaN`, when their marker is absent — reporting `0` for an undefined quantity (Double+ can structurally never exist on a TdT-only config, per D-03) would misrepresent an absence as a real finding.
- `DEFAULT_PERCELL_TSV`/`DEFAULT_REGION_TSV` are documented placeholders only: the real per-entry EXP-02 stem isn't knowable until `03_export_region_table.groovy` actually runs against a live QuPath entry (06.1-06); operators must pass `--percell-tsv`/`--region-tsv` explicitly.
