<objective>
Package the consolidated pipeline as a **user-friendly tutorial for non-coders** (D-16 + D-18), not just raw markdown:

1. The operator checklist becomes an **MkDocs Material documentation site** (`mkdocs.yml` + `docs/`) — a searchable website with a sidebar, previewable locally via `mkdocs serve` and publishable to GitHub Pages with one opt-in command.
2. The site home (`docs/index.md`) is the whole-pipeline checklist, each stage tagged GUI-vs-scriptable with exact commands and QuPath/ABBA click-paths, the `pipeline.yml` marker-config block documented (incl. the TdT-only declaration), the dual-location deploy convention spelled out, and the final consolidated script inventory reflected.
3. The two confusing GUI stages (ABBA registration, BraiAnDetect detection) get per-stage detail docs with annotated-screenshot slots.
4. A **one-command launcher** (`run_pipeline.py`) runs the scriptable steps behind plain-English prompts and hands off cleanly at the GUI seams it cannot automate.

Purpose: make the generalized pipeline reusable by any operator, including ones who aren't comfortable with code (PIPE-06, D-16, D-18).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator -> tutorial site | documentation; rendered locally or on Pages. No runtime input surface in the docs themselves. |
| operator -> run_pipeline.py | launcher executes a FIXED allowlist of project scripts via `conda run`; no user-supplied shell strings are interpolated. |
| repo -> public web (gh-deploy) | manual, opt-in publish of the tutorial to GitHub Pages — a data-disclosure vector for an unpublished-research repo. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06.1-12 | Repudiation | operator runs a retired script by mistake | low | mitigate | site lists the final script inventory + a retired-scripts note pointing at _archive/ |
| T-06.1-19 | Information Disclosure | accidental public publish of the tutorial (screenshots/methods) from a private repo via gh-deploy | medium | mitigate | publishing is OPT-IN manual only; no push-triggered Actions deploy exists; the site documents the repo-visibility + paid-plan privacy caveat so the operator decides consciously. gh-pages serves only the built docs, never the raw data tree. |
| T-06.1-20 | Tampering/Elevation | launcher shells out to arbitrary commands | low | mitigate | run_pipeline.py invokes a fixed set of project scripts via `conda run -n braian`; no user-provided command strings are passed to a shell |
| T-06.1-SC | Supply chain | new docs dependency (mkdocs-material) | low | accept | dev/docs-only, pure-Python, pinned in requirements-docs.txt, isolated from the pipeline runtime; not installed into the analysis path |

**ASVS L1 review conclusion:** One medium-severity disclosure threat (opt-in publish), fully mitigated by keeping publishing manual + documenting the visibility caveat; no push-triggered auto-deploy. All other threats low. No high-severity threats — nothing blocks under block-on-high.
</threat_model>
