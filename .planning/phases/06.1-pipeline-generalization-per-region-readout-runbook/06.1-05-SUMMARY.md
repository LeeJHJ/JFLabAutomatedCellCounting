## Decisions Made

- The prior executor's intended Rule-3 fix (add minimal placeholder PNGs so the strict MkDocs build resolves the screenshot-slot links) was completed as designed: six tiny valid PNG stubs, one per slot referenced in the two per-stage docs, plus a `docs/assets/README.md` note explaining they are stand-ins for the 06.1-06 operator run's real screenshots.
- `run_pipeline.py`'s menu scope was kept to exactly the SCRIPTABLE actions the plan named (validate config, aggregate+zero-leak, verify export integrity, show outputs) plus GUI stop items for the three GUI-mediated stages — not expanded to also wrap czi->MIP conversion or the "load ABBA ROIs" QuPath-run step, since those weren't in the plan's Task 4 action text or `read_first` list. This keeps the launcher's real-execution surface exactly as narrow as the threat model's T-06.1-20 mitigation describes (a fixed set of project scripts via `conda run`).
- GUI menu handlers return immediately after printing a handoff, with no `subprocess` call in that code path at all — a structural guarantee (not just a docstring claim) that the launcher cannot drive QuPath/Fiji automation.
