# Phase 06.1: Pipeline Generalization + Per-Region Readout Runbook - Context

**Gathered:** 2026-07-23
**Status:** Ready for planning

<domain>
## Phase Boundary

Consolidate the ad-hoc wBA1-3 script collection into a **single region-agnostic, config-driven, documented pipeline** that emits a **per-region count-and-density table** (DAPI+ / per-marker+ / Double+) for **any atlas region** in each slice. The marker set is **variable** — incoming slices may be TdT-only, so absent Fos+/Double+ must be *handled by construction*, not assumed. The consolidated spine is validated end-to-end on a new slice set and captured as a reusable runbook.

**In scope:** script consolidation/retirement, marker+region parameterization via a config file, the per-region table deliverable (+ combined CSV), boundary QC asserts, and the runbook.

**Out of scope (own phases):** section→animal BraiAnalyse aggregation (Phase 10 / AGG-01), atlas-coordinate export + brainrender point cloud (EXP-03/04), the area-based density readout for compact-nuclei regions (Phase 9 / AREA-01/02), imaging re-validation (Phase 7). This phase produces the *per-slice per-region* spine those phases consume.

</domain>

<decisions>
## Implementation Decisions

### Variable marker set (the load-bearing new capability)
- **D-01:** Markers are declared in an **explicit config block** — `name → channel → compartment` (nuclear / cytoplasmic). Operator declares the set per slice-set. No auto-detection from channel names; no script-top constants.
- **D-02:** The **detection/segmentation anchor channel is itself declared in the config** (not hardwired to DAPI). Default remains DAPI, but the pipeline must not assume it.
- **D-03:** **Double+ is auto-derived only when ≥2 non-anchor markers are declared.** On a single-marker (TdT-only) slice, Double+ is simply not emitted.
- **D-04:** Per-slice tables **omit columns** for absent markers — the schema adapts to the declared marker set (TdT-only ⇒ DAPI+/TdT+ only). *Consequence handled in D-13:* the growing combined artifact uses a long/tidy format so schema unions are a non-issue.

### Canonical spine + redundancy reconciliation
- **D-05:** **Keep the detect/classify split.** `run_braian_detection.groovy` (standalone CPU-heavy BraiAnDetect pass) and `02_detect_classify.groovy` (classify + label + report) remain the two canonical steps — this preserves the fast re-classify-without-re-detect tuning loop that the split was built for.
- **D-06:** **Retire the standalone `classify_markers.groovy`** — its core already lives verbatim inside `02_detect_classify.groovy`. One classification implementation, not two.
- **D-07:** **One config-driven export does everything** — a single export script emits both the per-cell TSV (feeds downstream atlas-coord/bioplausibility work) and the per-region count+density table. Grown out of `export_region_dapi_reference.groovy`'s all-region loop, generalized from DAPI-only to all declared markers. The DAPI-only specialization and the split `03_export_val01_metrics.groovy` role are folded in.

### Region parameterization
- **D-08:** **Emit all atlas regions present on the slice** (as `export_region_dapi_reference.groovy` already does). Region *focus* (LA/BA) becomes a downstream filter, never baked into the readout — region-agnostic by construction.
- **D-09:** Hardcoded literals go into the config: `EXCLUDE_ACRONYMS` (currently `["DG-sg","VS"]`) and all LA/BA focus literals move out of the groovy source into the sidecar config block.

### Output table structure
- **D-10:** **All regions as rows, each with an `is_leaf` flag, with parent rollups summed** — BUT the rollup MUST be computed leaf-anchored: **every cell is assigned to exactly one leaf** (smallest-area containing region, the CR-01 rule), and **parent rows are the SUM of descendant-leaf counts up the atlas tree — never an independent centroid-in-parent-ROI pass.** Parent density = summed count ÷ parent's own area. This is the only way "parent rollups summed" and CR-01's zero-leak guarantee coexist; the planner must not reintroduce independent parent containment counting.
- **D-11:** Density is cells/mm² (region count ÷ region area_mm²), consistent with existing exports.
- **D-12:** **Per-slice table + append to a growing combined CSV.** One self-contained table per slice/entry (matches current per-entry export), plus rows appended to a combined CSV tagged by slice + detection `config_tag` (the `export_region_dapi_reference.groovy` accumulation pattern).
- **D-13:** The **combined CSV is long/tidy**: one row per region × marker — `slice, config_tag, region, hemisphere, is_leaf, marker, class, count, density`. Absent markers produce no rows (no NA, no schema conflict); this is aggregation-ready for BraiAnalyse/pandas and cleanly resolves the per-slice "omit columns" choice (D-04).

### Config, robustness, runbook
- **D-14:** Config lives in a **new sidecar pipeline config** (e.g. `pipeline.yml` / `markers.yml`), separate from `BraiAn.yml`. `BraiAn.yml` stays BraiAnDetect's detection-params file; marker list, anchor, compartments, and exclusions are pipeline concerns and belong in their own file read by the groovy scripts.
- **D-15:** **Fail-loud boundary asserts.** Each scriptable entry checks its preconditions before doing work — ABBA ROIs loaded? detections present? image channels match the config's declared markers? — and aborts with a clear message otherwise. Makes "validated end-to-end" trustworthy across the human-in-the-loop GUI seams (ABBA registration, BraiAnDetect run). Not a full QC harness — targeted asserts at the hand-offs.
- **D-16:** Runbook = **a single operator-checklist `RUNBOOK.md`** (czi→MIP → ABBA register → BraiAnDetect → classify → export → per-region table), each step marked GUI-vs-scriptable with exact commands + QuPath/ABBA click-paths and the marker config block documented — **backed by per-stage detail docs** for the confusing steps (registration, detection). Reusable for any new slice set.

### Validation target (inferred default — user deferred; refinable at plan time)
- **D-17:** Validate end-to-end on the **incoming TdT-only slice set** (the first real exercise of the variable-marker path). Acceptance bar: a **schema-correct, non-empty per-region table** for the target region(s) with correctly *omitted* Fos+/Double+ columns, plus a **spot bioplausibility sanity check** (DAPI+ densities in the ~Phase-2 band, sane counts). This is the default; the concrete dataset + bar can be firmed up during `/gsd-plan-phase 06.1`.

### Packaging & tutorial delivery (added 2026-07-23 at plan-time, user request)
- **D-18:** The runbook is packaged as a **user-friendly documentation site for non-coders**, not just raw markdown, to avoid scaring off operators who aren't comfortable with code. Concretely:
  - **(a) MkDocs Material site** (`mkdocs.yml` + `docs/`) rendering the runbook + per-stage docs as a searchable website with a sidebar; previewable locally via `mkdocs serve` (no publish needed).
  - **(b) One-command launcher** (`run_pipeline.py`) that runs the SCRIPTABLE steps behind plain-English prompts so operators never assemble terminal/conda commands. It **explicitly hands off** at the `[GUI]` seams (QuPath/ABBA) it cannot automate — it must never claim to drive the GUI.
  - **(c) Annotated screenshots** for the two GUI stages, captured during the D-17 / 06.1-06 operator validation run (the natural moment to grab them).
  - **(d) GitHub Pages publishing is OPT-IN** (`mkdocs gh-deploy`, run manually when ready) — **never auto-published on push**, because repo/tutorial visibility is a research-data-privacy decision the operator owns (public repo = already public; private repo = Pages needs a paid plan and would expose the tutorial). Local-first, publish-when-ready.

### Claude's Discretion
- Exact sidecar config filename/format, the per-stage doc file layout, and precise assert messages are left to research/planning.
- Whether the retired `classify_markers.groovy` is deleted vs moved to `_archive/` — follow the workspace archive convention; grep for QuPath project references before moving.

<code_context>
## Existing Code Insights

### Reusable Assets
- **`export_region_dapi_reference.groovy`**: already iterates all region annotations, auto-reads detection config from `BraiAn.yml` into a `config_tag`, and appends to a growing central CSV with geometric centroid-in-ROI containment. This is the backbone for the generalized per-region table (D-07/D-12).
- **`02_detect_classify.groovy`**: `regionOf` centroid-in-ROI closure (ephemeral per-run region membership, never persisted), the `localBackgroundSubtractedMean` measure, and the channel-name-resolved measurement-key lookup (`it.startsWith(channelName) && endsWith("mean")`) — the exact hooks that become marker-config-driven (D-01/D-02).
- **`build_dapi_reference.py`**: existing aggregate+QC consumer of the growing CSV — pattern for the long/tidy combined reader (D-13).
- **`verify_export_integrity.py`**: multi-entry non-clobbering check — reuse for per-slice output verification.

### Established Patterns
- **Dual-location deploy:** author in canonical `scripts/`, hard-copy byte-identically into `<QuPath project>/scripts/`; "Run for project" for human-run steps. The runbook (D-16) must document this.
- **GUI vs scriptable split:** ABBA register + BraiAnDetect detection are human-in-the-loop; classification/export/table are scriptable — the exact seams the D-15 asserts guard.
- **Config-tag gating:** only like-config rows aggregate together — carry into the combined CSV (D-13).
- **CR-01 smallest-area-leaf labeling** computed geometrically — the invariant D-10 depends on.

### Integration Points
- Per-slice table + long/tidy combined CSV are the inputs Phase 10 (AGG-01 `SlicedBrain.from_qupath` → `AnimalBrain.from_slices`) and EXP-03/04 will consume.
- The sidecar `pipeline.yml` (D-14) is read alongside `BraiAn.yml` by every groovy entry.

</code_context>

<specifics>
## Specific Ideas

- The marker config's compartment semantics are fixed by the project rule: nuclear compartment for nuclear markers (e.g. Fos, AF488-T3), cytoplasmic expansion ring for cytosolic markers (e.g. TdTomato, AF568-T2). The config declares which, but the compartment→measure wiring stays nucleus-anchored per CLAUDE.md.
- "Any atlas region" is satisfied by emitting all regions (D-08), not by a region-selection UI.
- Parent rollups (D-10) are wanted for hierarchical reading, but only as leaf-summed rollups — this was an explicit reconciliation the user accepted.

</specifics>
