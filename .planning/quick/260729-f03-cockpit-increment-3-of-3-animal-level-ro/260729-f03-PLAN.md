# Cockpit increment 3 of 3 — animal-level rollup + stats-ready export shapes

Build `scripts/cockpit_animal.py`: roll the per-slice region readout (increment 2) up to the
**animal** level, stack animals into one group-ready table, compute the full engram-overlap
metric family, and emit both a tidy LONG table (Python/R) and Prism-friendly WIDE pivots.

This module exists to structurally enforce CLAUDE.md's stats convention — *aggregate to the
animal level before any group comparison; sections are not independent.* Every number is
**pooled from summed counts and summed areas, then recomputed** — never a mean of per-slice
ratios.

Increment 1 = `scripts/cockpit_checks.py` (QC gates, `0ccde36`…`fee7a1a`).
Increment 2 = `scripts/cockpit_regions.py` (per-slice region readout, `c7d567f`).

## Design decisions resolved here (the open questions)

### D-1 — Which marker is "tagged": config-derived, never positional
Resolution order, deterministic, documented in the module docstring:

1. **Explicit override** — `--tagged-marker` / `--activity-marker` (or the equivalent
   `roles=` argument) wins over everything.
2. **Optional `role:` key** in `pipeline.yml` (`role: tagged` / `role: activity`) if present.
   Additive and forward-compatible; no fixture is modified to add it.
3. **Compartment rule** — exactly one marker with `compartment ∈ {whole-cell, cytoplasmic}`
   → **tagged**; exactly one with `compartment: nuclear` → **activity**. Rationale, config-
   derived not name-derived: the tagging reporter in this pipeline is a cytosolic/whole-cell
   fluorophore, the activity readout is a nuclear IEG. M3 → tagged=TdT, activity=Fos. ✅
4. **Otherwise fail loud** naming the override flags. Never guess by position.

Single-marker configs: role comes from the same compartment rule (wBA TdT/whole-cell →
tagged), and only that one component rate is emitted.

### D-2 — Stacking animals with different marker sets: fail loud by default
Marker sets are compared as ordered `tuple(config.marker_names)` per project. A mismatch
(M3 `('Fos','TdT')` vs wBA `('TdT',)`) **raises**, printing each project's declared set.
Silently dropping Fos because one animal lacks it would corrupt a group comparison.
Opt-in `--stack-on-intersection` stacks on the shared marker set and prints exactly which
columns were dropped and why. If the intersection has < 2 markers, the overlap metrics skip
(columns absent, one explanatory line) rather than emitting a wall of NaN.

### D-3 — group/condition assignment: explicit operator mapping only, never inferred
Never parsed out of an animal-ID string.

- `--groups <file>` — YAML `{groups: {M3-hipp1: recall, wBA1-2_2-1: control}}` **or** a
  two-column CSV `animal,group`. Format detected by suffix.
- `--group animal=group` — repeatable, for one-offs.
- **A supplied mapping that omits an animal is a hard error** listing the unmapped animals
  (a silent blank group would corrupt an ANOVA).
- **No mapping supplied at all** → `group = "unassigned"` + a loud warning that group
  comparisons are not possible. This keeps the legitimate single-animal exploratory run
  (M3 first run) working.

### D-4 — N (denominator) source, per row
Per-cell classifiable N is computable only at `hemisphere == both` (recon 3), so:
`--n-source auto` (default) uses the classifiable joint population for `both` rows and the
anchor (DAPI) count for `L`/`R` rows; `--n-source anchor` forces one uniform basis;
`--n-source classifiable` forces classifiable and leaves L/R metrics NaN. **Every row carries
an `N_source` column** (`classifiable` | `anchor_count`) and the CLI prints the per-animal
classifiable/anchor ratio so the operator can see how little it moves.
"Classifiable joint population" = `AND` of `ksr.classifiable_mask(df, m)` over every marker
present — the same population `T`, `A`, `D` were classified on.

### D-5 — Additive `log2_odds_ratio_hc`
`log2_odds_ratio` is NaN whenever any 2×2 cell is 0 (common in small regions), which would
strand the best-behaved parametric metric. The plan also emits `log2_odds_ratio_hc`, the same
quantity with the standard Haldane–Anscombe +0.5 continuity correction on all four cells —
always finite. Both are documented; neither replaces the other.

## Metric family (locked names, marker-agnostic)

With `N` = denominator cells, `T` = tagged+ count, `A` = activity+ count, `D` = Double+ count;
2×2 cells `a=D`, `b=T−D`, `c=A−D`, `d=N−T−A+D`:

| Column | Definition | Notes |
|---|---|---|
| `tagging_rate` | `T/N` | DAPI-dependent |
| `activity_rate` | `A/N` | DAPI-dependent |
| `reactivation_rate` | `D/T` | = P(activity+ \| tagged+); **immune to N** |
| `reverse_rate` | `D/A` | = P(tagged+ \| activity+); immune to N |
| `overlap_above_chance` | `(D·N)/(T·A)` = `reactivation_rate / activity_rate` | **PRIMARY**; DAPI-dependent |
| `log2_odds_ratio` | `log2( a·d / (b·c) )` | NaN if any cell is 0 |
| `log2_odds_ratio_hc` | same, all cells `+0.5` | always finite |
| `jaccard` | `D/(T+A−D)` | immune to N |

`d < 0` (possible if N under-counts) → NaN for both odds ratios, plus a counted warning.
Column names for counts/densities stay config-derived exactly as increment 2 writes them
(`{anchor}_count`, `{M}+_count`, `Double+_count`, `…_density`).

## Caveat that must be surfaced, not buried

Every chance-corrected metric (`overlap_above_chance`, both odds ratios, `tagging_rate`,
`activity_rate`) has `N` in its denominator. The white-matter and ventricle QC gates are
currently **parked as advisory** (`cockpit_checks.GateThresholds.advisory_gates`), i.e. DAPI
is known to be over-detected (cc ≈ 4.8 k/mm² vs cortex ≈ 4.0 k/mm²). Inflated N deflates
P(activity+) and therefore **inflates `overlap_above_chance`**. `reactivation_rate`,
`reverse_rate` and `jaccard` are immune — no N.

**Recon 4 makes this sharper and it must be stated plainly in the module docstring and in the
CLI output: switching N to the classifiable set does NOT fix this** (0.005 % on M3). It buys
the correct joint-population denominator, nothing more. The actual levers are re-arming the
white-matter gate, raising `k_robust`, or lowering `cellExpansionMicrons` — named in the
docstring so the number is never read as if it were clean.
