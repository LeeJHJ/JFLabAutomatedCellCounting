# Summary: cockpit_animal.py — animal-level rollup + stats-ready export shapes (cockpit increment 3 of 3)

## What shipped
`scripts/cockpit_animal.py` — rolls increment 2's per-slice region readout
(`cockpit_regions.build_readout`) up to the **animal** level (pool counts/areas across slices,
then recompute every density and ratio metric — never a mean of per-slice ratios, per
CLAUDE.md's pseudoreplication rule), resolves the tagged/activity marker roles from
**compartment**, not marker declaration order (D-1), computes the full eight-column
engram-overlap metric family, stacks multiple animals/projects into one group-ready table
with fail-loud marker-set-mismatch protection (D-2), applies explicit operator group mapping
(D-3), and exports both a tidy LONG table and Prism-friendly WIDE pivots. Also added
`notebooks/03_animal.ipynb`, a thin cockpit notebook in the 01/02 idiom that calls the module
end-to-end (config panel → rollup → metric panel → export → caveat panel).

## Design decisions (resolved per plan, implemented as written)
- **D-1 role resolution** (`resolve_roles`): explicit `--tagged-marker`/`--activity-marker` >
  optional per-marker `role:` key in pipeline.yml > compartment rule (`whole-cell`/
  `cytoplasmic` → tagged, `nuclear` → activity) > fail loud. Verified against the real M3
  fixture, whose `pipeline.yml` declares `markers: [Fos, TdT]` (Fos first) — resolution
  correctly picks `tagged=TdT`, `activity=Fos` despite TdT being `markers[1]`.
- **D-2 stacking** (`stack_animals`): a marker-set mismatch across `--project` args raises by
  default, naming every project's declared set; `--stack-on-intersection` opts in, dropping
  the non-shared marker's count/density/rate columns (printed per project) and skipping all
  pair metrics entirely (columns absent, not NaN) when the intersection has < 2 markers.
- **D-3 group mapping** (`load_group_map`/`apply_group_map`): YAML `{groups: {animal: group}}`
  or two-column CSV, plus repeatable `--group animal=group` overrides; a mapping that omits a
  stacked animal is a hard error; no mapping at all → `group="unassigned"` + a loud warning
  (keeps the single-animal exploratory run working).
- **D-4 N-source** (`--n-source auto|anchor|classifiable`): `classifiable_n_by_region` rolls
  the per-cell joint-classifiable population up over the *same*
  `creg.included_leaves(...)` frontier increment 2 uses (zero denominator drift), and is only
  ever computed at `hemisphere == "both"` (percell's `region_label` is a bare acronym with no
  hemisphere prefix — recon 3 of the plan). `auto` (default) uses classifiable N for `both`
  rows when a percell export exists, anchor (DAPI) count otherwise; every row carries an
  `N_source` column.
- **D-5 `log2_odds_ratio_hc`**: Haldane–Anscombe +0.5 continuity-corrected odds ratio, emitted
  alongside the raw `log2_odds_ratio` (NaN whenever any 2×2 cell is 0) — neither replaces the
  other.
- **Parked-gate caveat**: surfaced in the module docstring, the CLI's printed output, and the
  notebook's caveat panel, including the recon-4 finding that switching to classifiable N does
  **not** fix DAPI over-detection (only a ~0.005% difference on M3) — the real levers named are
  re-arming the white-matter gate, raising `k_robust`, or lowering `cellExpansionMicrons`.

## Post-execution verification findings (orchestrator, 2026-07-29)

Independent re-verification against the M3 7-scene fixture found one real defect and one
silent-failure mode. Both fixed in `5b9209b`; real metric values unchanged.

| # | Finding | Fix |
|---|---|---|
| 1 | **`log2_odds_ratio_hc` returned `0.0` for an all-zero region.** Haldane-Anscombe +0.5 on `N=T=A=D=0` gives `(0.5*0.5)/(0.5*0.5)=1` → `log2 = 0`, reading as "exactly at chance". The `d >= 0` guard admitted it because `0-0-0+0 == 0`. Every other metric NaN'd correctly, so this one column would have contributed a fabricated at-chance data point to a t-test. | Guard now also requires `N > 0`. Self-test asserts all three chance-corrected metrics NaN on an all-zero region. |
| 2 | **Regions rolling up to zero were silent.** On M3, `STRd` reports 0 while actually carrying 41,761 anchor cells — its only present ontology child `CP` holds 0 at an *identical* area. This is increment 2's documented frontier-coverage caveat (QuPath annotation hierarchy ≠ Allen ontology), inherited not introduced, but at animal level a silent 0 is materially more dangerous. | `_warn_empty_regions()` names every zero-count region on stderr and points at `cockpit_regions.coverage_report()`. |

**Cross-check against known result:** M3 `CA1 overlap_above_chance = 4.24x` reproduces the
independently recorded ~4.2x CA1 enrichment, confirming the metric family is computed on the
same population as the existing readout rather than a re-derived one.

**Correction to a pre-planning assumption.** The orchestrator specified computing `N` from the
classifiable cell set to mitigate DAPI over-detection. The planner's fixture check disproved
this: classifiable filtering removes only `Excluded` + non-finite bg-sub rows — **41,759 vs
41,761 on M3 STRd, a 0.005% difference**. It removes no haze-detected nuclei. The lever was
implemented anyway (correct joint-population denominator, and the printed ratio *demonstrates*
the caveat stands) but it is documented as NOT a mitigation. `overlap_above_chance` remains
inflated while the white-matter gate is parked; the real levers are re-arming that gate,
raising `k_robust`, or lowering `cellExpansionMicrons`.
